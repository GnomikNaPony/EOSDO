# Демо документов с версиями

Статус: завершено.

## Цель и основания

Пользователь просит добавить документы разных версий в тестовую базу, чтобы показать diff и историю замечаний на демо. Источник ожидаемого результата — этот запрос и существующий контракт приватных демопространств. Область: генератор createDemo, фикстуры/проверки и документация. Публикация, изменение настоящих аккаунтов и массовое обновление уже созданных демо вне задачи.

Риск обычный: дополняются вымышленные записи существующих типов в уже изолированном генераторе, без миграции, изменения доступа или согласования.

## Исходное состояние

main 9f78e12276a2c0d744a070189d7b84bac901295c, дерево чистое. Версии/diff уже в commit. createDemo создает 3 документа по одной версии и одно открытое замечание. Каждый полный reload создает новое демо. Проверки Bun 1.4.4; PostgreSQL/Redis/MinIO, UI Playwright. Карта проекта прочитана и сверена с кодом.

## Критерии

| ID | Наблюдаемое поведение | Источник | Проверка |
|---|---|---|---|
| AC-01 | В каждом новом демо 3 документа с 3/2/2 версиями; номера/parent_id/хеши/оригиналы соответствуют тексту | запрос владельца | integration |
| AC-02 | Diff показывает конкретные замены сроков/участников/трудозатрат, добавления и удаления, включая v1→v3 | запрос показать до/после | API + UI |
| AC-03 | Есть open/addressed/closed замечания с цитатами/номерами строк, ответами и непротиворечивой хронологией; решение куратора связано с его вымышленным профилем | существующий домен и запрос показать функцию | integration + UI |
| AC-04 | Новые демо изолированы друг от друга/настоящих пользователей; S3 failure компенсирует все записанные и попытанные ключи | docs/domain.md | существующий integration с расширением |

## Поток и решение

POST auth/demo → demoScope → PG транзакция + S3 оригиналы каждой версии → цепочки parent_id → исторические комментарии/ответы/события → bootstrap/detail → существующие Versions/Diff/Comments. В демоскоп добавляется вымышленный куратор без пароля и сессии для правильного отображения исторических решений; текущий посетитель остается исполнителем. Новые роли доступа не вводятся. Фикстуры описывают учебную историю, не реальные решения и не ИИ-отчеты.

## Сценарии и инварианты

- Нормальный: все 7 файлов можно скачать, hash/size/text совпадают, diff v1/v2 и v1/v3 имеет ручные ожидаемые строки.
- Пустой настоящий профиль: остается пустым. Старые демо не модифицируются; следующий reload создает новую полную fixture.
- Границы: один исходный parent=null, каждый последующий указывает предыдущий ID той же карточки; цитаты существуют на указанной строке; resolved_version принадлежит той же цепочке.
- Повторы/конкурентность: UUID и demoScope изолируют повторные/параллельные запуски; прежние concurrent bootstrap проверки сохраняются.
- Неверные данные/внешние входы: генератор не принимает пользовательского содержимого; API validation не меняется.
- Частичный отказ: exception откатывает PG; keys включает попытанный S3 key до write, удаляются все ключи включая уже записанные версии; проверяются ранний и поздний сбои.
- Большие объемы: фиксированные 7 небольших TXT, ограниченный набор событий; новых лимитов/алгоритмов нет.

## Проверки

check, lint, format:check, build, bun test, test:integration и test:ui с существующим Chromium. Отдельные проходы самопроверки требований и реализации; новые зависимости не нужны. Миграция/откат данных не нужны: старые демо остаются, новые используют новый seed.

При самопроверке уточнены детали: отчёт с заявленным исправлением имеет этап review; события/история сортируются по предметному created (семена имеют одинаковый PG transaction timestamp); в UI добавлен разделитель между датой и номером строки. Эти изменения нужны для непротиворечивого и читаемого показа seed.
