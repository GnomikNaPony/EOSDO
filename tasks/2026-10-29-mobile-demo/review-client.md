# Независимое ревью клиентской части

Проверяющий: субагент demo_backend, не реализовывавший клиентские изменения. Backend в это ревью не входит. База: edbe66a4fd21dc54c0b42bc13aa1d04016129d7c, текущее рабочее дерево 29.10.2026.

Область: App, app-store, Auth, DemoPage, demo.css, WorkspaceShell, styles.css, Registry, Kanban, общие UI-компоненты, scripts/verify-ui.ts; критерии AC-01–AC-05. Выполнено чтение кода и diff, трассировка инициализации/сессии, переходов меню/карточки и браузерных проверок. Отдельный браузерный прогон проверяющий не запускал; итоговый UI smoke выполняет основной агент. Статическое ревью не доказывает отсутствие визуальных дефектов на реальном устройстве.

## Найденные проблемы и исправления

1. **P2, вход в собственный аккаунт из демо.** Первоначальный `app-store.tsx:initialize` на `/login` выполнял только bootstrap и сохранял текущую demo-cookie. Поэтому ссылка «Свой аккаунт» открывала демопространство без формы входа и без отметки демо. Репро: `/` → меню → «Свой аккаунт» → вместо Auth тот же профиль. Сообщено основному агенту. В текущем дереве исправлено в `src/client/app-store.tsx:182`: только для `/login` и `user.demo_id` завершается demo-session, затем перечитывается bootstrap. Обычные реальные сессии не завершаются. В `scripts/verify-ui.ts:334` добавлен сценарий перехода и ожидания email. Исправление просмотрено; runtime подтверждается общим UI smoke.

2. **P2, некорректное закрытие модального окна в новом UI smoke.** Новый цикл 360/390px первоначально нажимал Escape после открытия DocumentModal. Сам DocumentModal Escape не обрабатывает, Shell закрывает только меню; окно оставалось и блокировало следующую итерацию. Сообщено основному агенту. Текущее исправление `scripts/verify-ui.ts:329` нажимает реальную кнопку «Закрыть» внутри dialog. Это соответствует имеющемуся поведению продукта и не ослабляет проверку мобильного открытия формы.

После этих исправлений блокирующих замечаний по просмотренной клиентской части не обнаружено.

## Проверенные свойства и границы

- `/demo` возвращается до создания AppProvider: QR-страница сама не вызывает создание профиля. Цель QR формируется из текущего `location.origin`, с тихой зоной в четыре модуля; внешнему сервису домен не отправляется.
- Полная загрузка демо вызывает endpoint один раз через onMount; hash-навигация вызывает только route и сохраняет профиль. После создания нового профиля старый hash документа сбрасывается, чтобы не обращаться к документу предыдущей личности.
- Ошибка инициализации оставляет явное состояние ошибки с повтором; нет показа фиктивно успешного пространства.
- Мобильное меню переключается по media query, закрывается при смене hash и через overlay/Escape. Таблицы реестра превращаются в карточки; вкладки и канбан сохраняют внутреннюю прокрутку. Формы используют 16px поля и увеличенные элементы управления.
- Existing create/upload/download, прямые ссылки обычного аккаунта и нормальная регистрация сохранены в UI smoke. Дополнительные сценарии проверяют reload/new identity, отказ доступа к прежнему документу, 360/390px, меню, карточку, формы, QR target и отсутствие создания профиля на служебной странице.
- Проверка внешнего overflow не измеряет горизонтальное переполнение каждого вложенного контейнера. Внутренняя прокрутка таблиц/вкладок предусмотрена дизайном; пригодность на реальном телефоне остаётся границей автоматического smoke.
- Этот проход не является независимым backend-аудитом и не заменяет обязательные интеграционные/браузерные проверки финального дерева.
