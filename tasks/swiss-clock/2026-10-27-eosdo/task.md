# ЕОСОД: интерфейс по видео и работа с документами

Статус: завершено в границах локального прототипа. Доказательства и ограничения — в completion.md.

## Цель и основания

Создать в пустом репозитории работающий локальный сайт по предоставленной записи и добавить четыре запрошенных направления: версии файлов и замечания, локальную ИИ-проверку, уведомления, канбан куратора. Источники: запрос пользователя 27.10.2026, видео 337,9 с, материалы идеатона. Пользователь подтвердил отсутствие шаблонов: правила редактируются, начальные примеры демонстрационные.

Границы: самостоятельный локальный прототип с настоящим SQLite-хранилищем, скачиванием файлов и Ollama. Без подключения к промышленной ЕОСОД, корпоративной авторизации, электронной подписи, почтовой доставки, публикации или переноса рабочих документов. Переключатель ролей — явно демонстрационный, не промышленная аутентификация.

Риск: обычный для изолированного прототипа с синтетическими данными; хранение версий, права действий, конфликты и отказы дополнительно проверяются интеграционно. Использование в организации потребует отдельного анализа доступа и независимого ревью. Исходные файлы пользователя не меняются и не копируются в Git.

## Поток и решение

Браузер → JSON API → серверная проверка роли/входов → транзакция SQLite (файл BLOB, версия, история, уведомления) → фоновая очередь извлечения текста → локальный Ollama → отчёт, уведомление и обновление карточки. Статические HTML/CSS/JS без сборщика; Python HTTP + SQLite из stdlib, pypdf/python-docx/openpyxl только для чтения распространённых документов. Единственный worker ограничивает параллельную нагрузку модели. Версии линейные, без ветвления/слияния бинарных файлов; текстовый diff доступен для извлекаемого текста.

Инварианты: версия не перезаписывается; запись и файл атомарны; номер уникален в документе; устаревшая проверка не меняет статус новой версии; статус согласования относится к последней версии; ИИ не принимает итоговое решение; ошибки извлечения и модели явны. Время UTC в БД, локализуется браузером; сроки — календарные даты.

| Старые данные | Новый файл во время старой проверки | Старый отчёт не меняет новую карточку | API |

## Неопределённость

- Реальные формы, нормативные критерии и справочники отсутствуют: редактируемые демонстрационные правила, не проверка на соответствие нормативам.
- Скрытые возможности исходной ЕОСОД не известны; реализуются показанные экраны и запрошенные сценарии.
- Полная достоверность ИИ не гарантируется; каждое решение подтверждает куратор. PDF-сканы без текста требуют ручной проверки, OCR за границами первой версии.

## Обязательные проверки

Python compile, Node syntax, unittest интеграционных API на временной БД, реальный тест локальной модели на синтетическом документе, браузерные сценарии через Playwright, визуальная проверка настольного и узкого экранов. Два прохода саморевью по требованиям и качеству. Независимое ревью для внедрения в промышленную систему не выполняется в рамках локального прототипа.
