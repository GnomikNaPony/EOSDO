# Публикация текущей ЕОСДО

Статус: реализация.

## Цель и основания

По прямому поручению владельца отправить все текущие изменения в GitHub и обновить действующую ЕОСДО на Railway. Исходная база: `85085c82a0df8ee6fb71f085724f82c5be97c4f3`, main совпадает с origin/main. Единственный пользовательский незакоммиченный файл — `ЕОСДО_ИТ_КоР_2026_7слайдов_финал.pptx`; содержимое сохраняется без изменения. Новых функций в этой задаче нет.

Цель Railway из docs/railway-sites.md: project `9fc3f5f1-1ea4-4d2d-816b-8225dd610695`, production `519dee81-ff21-4096-b29c-fa578aeb06a1`, только eosdo-current `3d6657d7-de58-4e9d-8ce1-b6ceb20b7193`. Исходное демо и другие сервисы не являются целями обновления. Риск обычный для ручного релиза существующего приложения; новых схем/миграций не добавляется. Предыдущий успешный deployment должен быть установлен перед публикацией для возможности восстановления.

## Критерии приемки

| ID | Поведение | Источник | Проверка |
| --- | --- | --- | --- |

| AC-04 | Публичный сайт и API health отвечают после активации | docs/railway.md | HTTP 200 страницы и /api/health |

## Поток и границы

Локальные файлы → проверки → Git commit/push → Railway upload точного checkout → build:release → существующий pre-deploy → health → активация. Локальная PostgreSQL/Redis/MinIO используется только временными интеграционными/UI базами. Локальные env, данные и логи не публикуются. Автоматический CI не подменяется вымышленным успешным результатом; допускается прямо запрошенный ручной релиз по docs/railway-sites.md.

Нормальный случай — все проверки и health успешны. Ошибка проверки блокирует релиз; ошибка deploy требует диагностики и сохранения предыдущей версии. Пустые/неизвестные ID целей недопустимы; используются явные проверенные ID. Повтор и конкурирующий deploy должны сверяться с активными deployment; несвязанные ресурсы не перезапускаются. Новые алгоритмы, числовые границы и новые пользовательские форматы в этой задаче отсутствуют; их существующие контракты покрываются прикладными проверками. Локальный Ollama не считается доступным из Railway: фактическая настройка и ограничение ИИ проверяются отдельно без развёртывания новой модельной инфраструктуры.

## План проверки и ревью

Проверить цель и предыдущий deployment, выполнить build:release/integration/UI, отдельно просмотреть состав публикации и ограничения. После последней правки исполняемых файлов повторить затронутые проверки. Самопроверка не является независимым ревью. Новых зависимостей и изменений контракта не планируется. Результаты, точный SHA и ограничения фиксируются в completion.md.
