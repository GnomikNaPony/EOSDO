# Поиск файлов, проверяемый релиз и презентация КБ Эффективность

Статус: реализация.

## Цель и основания

Запрос пользователя: получить последнюю версию EOSDO, переработать поиск по файлам, добавить тесты, развернуть Railway с блокировкой при упавшем check, сделать динамичную презентацию ровно 8 слайдов по голосовому в присланном шаблоне и с реальными скриншотами до/после EOSDO1.0. Участники: Кико Александр Георгиевич, Веткаль Михаил Максимович, Брекер Евгений Евгеньевич. Команда КБ Эффективность.

Голосовое Еосдо 2.m4a 02:43.88 расшифровано локально двумя моделями, raw/таймкоды/plain сохранены вне Git. 00:00–00:55 естественность UX, лишний контекст, быстрые улучшения; 01:03–02:02 переход к данным и векторизации; 02:11–02:29 последняя идея явно названа будущей. Поэтому текущая реализация — серверный поиск по файлам/содержимому; семантический поиск остаётся отдельным следующим этапом, не выдаётся за готовый. Нечёткие имена/числа не используются. Количество слайдов уточнено пользователем: 8.

## Поток и границы

Поиск: пользовательский ввод/фильтры → валидация API → ограничение документов текущей сессией → версии/текст/ранжирование → excerpt+версия → кликабельный UI. Оригиналы остаются неизменяемыми; данные не отправляются облачной ИИ. Пустой/неизвлекаемый текст не должен давать ложный match, HTML экранируется. Семантический поиск — концепт следующего этапа, отдельные правила/эмбеддинги сейчас не добавляются.

Релиз: push → весь check → только success разрешает deploy → migration/health → активный сервис. Никакого always/continue-on-error на допуске. Запускать дополнительную новую инфраструктуру отдельно от чужих сервисов; восстановление — прежняя активная версия плюс отдельные резервные копии PG/S3, без destructive reset.

Презентация: голосовое+прежний диалог+реальный код+скриншоты → проверенная история → исходные masters/layouts/fonts →8 слайдов+заметки/переходы → render/inspect/finalize. Исходный шаблон не перезаписывается. Чувствительные исходники и секреты не публикуются.

## Матрица

Нормальные: запрос по имени/уникальному слову текста. Пустые: реестр без текста/нулевые результаты, понятное сообщение. Границы: длина/число слов/лимит результатов. Неверные: типы/дата/несуществующая версия. Большие: сервер ограничивает ответ, не выгружает всё содержимое. Повторы: нет дубликатов/устаревшего ответа в UI. Конкурентность: быстрый ввод/новая версия. Отказы: API/services недоступны, check падает, токен отсутствует — нет фиктивного успеха/активации. Старые данные: чтение ранее загруженных файлов, права неизменны, миграция идемпотентна.

## Проверки

Используем реальные команды docs/verification.md и CI. Дополнительные тесты привязаны к независимым синтетическим документам с известными словами/именами. Никакие проверки не ослабляются ради деплоя. Итог, оставшиеся ограничения и точный снимок — completion.md.
