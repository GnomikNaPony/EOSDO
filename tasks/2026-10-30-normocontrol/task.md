# Нормоконтроль загружаемых документов

Статус: реализация.

## Цель и основания

По запросу владельца встроить нормоконтроль из https://github.com/GnomikNaPony/normocontrol-offline (5494ca23684eb653602e057e39942eb3da2c93a7) в ЕОСОД, отправить в Git и действующий Railway eosdo-current.
Риск обычный: рекомендации к неизменяемым версиям, без изменения согласования, автоматического исправления или миграций.
Переносим детерминированные правила analyzer.py и структурные признаки extractors.py. Desktop GUI/SQLite/OCR/обучение/выпуск исправленных копий не входят в интеграцию; актуальность нормативных ссылок без утверждённого справочника не заявляется.

## Поток и решение

Upload → существующая валидация/извлечение → ограниченный детерминированный анализ → отдельная normocontrol запись JSONB с version_id → detail → вкладка Нормоконтроль. Ручной повтор через ACL версии читает оригинал S3, сохраняет только отдельный отчёт. ИИ и допуск согласования не меняются. Проверки Word читают namespace-aware XML после существующей проверки ZIP (20MB input/50MB expanded/2000 members). Один новый прямой dependency фиксирует уже установленный XML parser, чтобы не зависеть от транзитивного контракта Mammoth.

## Матрица

| Категория | Ожидаемый результат / проверка |
| --- | --- |
| TXT/MD/CSV/PDF | Проверка извлечённого текста; оформление явно вне охвата |
| DOCX | Текст + стили/ручная нумерация/поля/колонтитулы/таблицы/поля страницы/подписи |
| Пустой/повреждённый/XLSX/скан | unavailable с причиной, оригинал сохранён |
| Большой текст/ZIP | Существующие лимиты extraction; лимит числа находок обозначается как limited |
| Повтор | Ручной пересчёт отчёта той же версии без новой версии/изменения оригинала |
| Конкурентность | Детерминированный отчёт; обновление только записи отчёта в транзакции |
| Частичный отказ S3/PG | API error; нет фиктивного успеха; прежняя компенсация upload сохраняется |
| Старые версии | Отсутствие отчёта отображается явно; ручной запуск доступен |
| Чужая версия | Действующий ACL до чтения S3 |

Обязательные проверки: check, lint, format:check, unit, integration, build, UI; два прохода саморевью. Новых критериев автоматического согласования нет. Восстановление: предыдущий Railway deployment; данные совместимы без schema migration.
