# ЕОСОД

Рабочее пространство документов на TypeScript, Bun 1.4.4, Solid JS, Tailwind, Fastify и Drizzle. PostgreSQL хранит данные, Redis — сессии, MinIO S3 — оригиналы файлов. UI основан на [EOSDO1.0](https://github.com/GnomikNaPony/EOSDO1.0/tree/15a3b97d34b7d0ad64f89194710552441e1b9873).

Главная страница открывает новое приватное демопространство при каждой полной загрузке: вымышленные рабочие документы, оригиналы файлов и личные шаблоны уже готовы для знакомства. Внутренние переходы сохраняют текущий профиль, перезагрузка начинает новое демо. Демоданные изолированы от других посетителей и настоящих аккаунтов.

`/demo` — служебная страница с QR-кодом и ссылкой на текущий домен: откройте её на экране, чтобы посетители могли испытать демо с телефона. Код создаётся локально, без внешнего сервиса. `/login` — обычная регистрация и вход по email/паролю с сохранением документов между посещениями. Новое настоящее рабочее пространство остаётся пустым. MD/TXT примеры для ручной загрузки находятся в [templates](templates/README.md); сервер не импортирует их автоматически.

## Запуск

Bun **1.4.4** и работающий Docker обязательны. Docker запускает только PostgreSQL, Redis и MinIO; UI и API работают вне Compose.

```sh
cp .env.example .env
# Укажите локальные пароли; DATABASE_URL должен использовать POSTGRES_PASSWORD.
bun install --frozen-lockfile
bun scripts/start.ts
```

Открыть http://127.0.0.1:8765. Скрипт поднимает сервисы, создаёт bucket, применяет схему, собирает UI и запускает сервер. Отдельные команды:

```sh
bun run services:up
bun run db:migrate
bun run build
bun run start
```

MinIO собирается из официального исходного release: его исторические публичные образы недоступны. Первая сборка требует сети. Проверенный собственный образ можно выбрать через `MINIO_IMAGE`.

Разработка — `bun run dev:server` и `bun run dev` в двух терминалах. Vite проксирует `/api` на 8765. `Запустить ЕОСОД.command` — macOS launcher TypeScript скрипта. Деплой Railway описан в [docs/railway.md](docs/railway.md); публикация в этой задаче не выполнялась.

## Профили и документы

Локальные аккаунты используют email и пароль; пароль хешируется через Bun.password, сессия хранится в Redis. Первый зарегистрированный аккаунт настраивает организацию и получает роль куратора, последующие — исполнителей. Самостоятельная регистрация рассчитана на локальное рабочее пространство; корпоративные приглашения/SSO пока не подключены.

Создайте карточку, затем выберите «Файлы и версии» → «Загрузить новую версию». Автор берётся из текущей серверной сессии. Шаблоны в интерфейсе сохраняют личные настройки реквизитов/маршрута; папка `templates` содержит только документы-примеры и с ними не связана. Загрузки и операции сохраняются в реальных сервисах, localStorage не заменяет backend.

Перед ИИ-проверкой задайте свои правила в соответствующем разделе и настройте `OLLAMA_URL`/`OLLAMA_MODEL`. Пустой набор правил не считается успешной проверкой. TXT/MD/CSV, PDF с текстовым слоем и DOCX поддерживают извлечение текста; для сканов нужен OCR, XLSX и встроенный PDF viewer пока не поддерживаются. Раздел «Данные из документов» использует отдельную фоновую обработку Ollama (`OLLAMA_MODEL`, `OLLAMA_EMBED_MODEL`, по умолчанию `qwen3.5:9b` и `embeddinggemma`) независимо от правил нормоконтроля. Факты содержат цитаты и ссылки на версии; группы переписки являются предложениями для проверки. Обзор доступен куратору, смысловой поиск автора ограничен его документами. Согласование не является электронной подписью.

## Структура для развития

- `src/client/components/` — общие UI-компоненты; `layout/` — оболочка.
- `src/client/features/` — реестр, карточка и её вкладки, профили, шаблоны реквизитов, уведомления и правила.
- `src/client/app-store.tsx`, `api.ts`, `types.ts` — состояние Solid, HTTP и типы.
- `src/client/styles.css` — Tailwind theme/component utilities; без отдельного UI framework.
- `src/server/app.ts`, `index.ts` — создание приложения и запуск; `routes/` — HTTP-модули.
- `src/server/domain.ts`, `document-service.ts`, `workspace.ts` — валидация/операции документов/профили; `store.ts`/`schema.ts` — Drizzle/PostgreSQL; `ai.ts` — worker.
- `templates/` — только примеры для ручной загрузки.

Используем Bun SQL, RedisClient, S3Client, password, test, fmt и check. Oxlint — разрешённый владельцем линтер. Vite/Solid compiler и Tailwind plugin — инструменты сборки; Playwright — dev-проверки. Отдельных pg/redis/aws SDK или state manager нет.

## Проверки и данные

```sh
bun run lint
bun run check
bun run build
bun run format:check
bun test
bun run test:integration
bunx playwright install chromium
bun run test:ui
```

Интеграционные и UI тесты создают временные PostgreSQL базы, сессии и S3-объекты; примеры не попадают в рабочий реестр. Для установленного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

Прежняя локальная база `eosdo` сохранена отдельно; приложение на этом компьютере использует новую `eosdo_workspace`. Старые данные не удалены. Python/SQLite версия доступна в Git на `2cb8d23b79d3c396a7e9564e49072a1e01aa8ae8`. `bun run db:import -- path/to/eosdo.sqlite3` — legacy импорт, который перед реальными данными требует проверки на копии и сопоставления старых владельцев с аккаунтами; автоматическая миграция аккаунтов отсутствует.

Резервируйте PostgreSQL и MinIO согласованно. `docker compose down` сохраняет тома. Swiss Clock подключён через AGENTS/.agent/docs/checks/tasks; это протокол, а не гарантия корректности. CI и внешняя защита слияния требуют отдельного подтверждения. Текущая задача: [критерии](tasks/2026-10-28-components/task.md), [результат](tasks/2026-10-28-components/completion.md).
