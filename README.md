# ЕОСДО · локальное рабочее пространство

Работающий локальный прототип по видеозаписи от 27.10.2026: синий навигатор, реестры и карточки документов с вкладками. Добавлены результаты работы с историей версий, замечания, локальная ИИ-проверка, уведомления и канбан. Мелкие подписи исходного интерфейса не везде читаются в видео 478×270; это реконструкция доступной структуры и стиля, а не исходный код промышленной ЕОСДО.

## Запуск на этом Mac

Дважды нажмите **[Запустить ЕОСДО.command](./Запустить%20ЕОСДО.command)**. Откроются окно Terminal и сайт **http://127.0.0.1:8765**. Пока используете сайт, оставляйте окно Terminal открытым; `Ctrl+C` останавливает сервер. Данные при остановке сохраняются.

Из терминала:

```sh
./scripts/start.sh --open
```

Первый запуск создаёт `.venv` и устанавливает библиотеки из `requirements.lock`. Требуется Python 3.12+; при наличии `uv` используется он. На данном компьютере окружение уже подготовлено.

Если порт занят, уже запущенный сайт можно открыть по тому же адресу. Другой экземпляр на отдельном хранилище:

```sh
./scripts/start.sh --port 8766 --db data/second.sqlite3 --open
```

## Как пользоваться

1. Вверху справа выберите демонстрационную роль: Елена — куратор, Александр и Мария — исполнители. Исполнитель видит свои документы; куратор — общий реестр. Это выбор роли для локальной демонстрации, **не корпоративная авторизация**.
2. Нажмите «Создать проект документа», укажите название, вид, исполнителя, срок и приоритет. Подразделение подставляется автоматически. Поиск реестра работает по номеру, наименованию, исполнителю и подразделению; диапазон дат не ограничен месяцем.
3. В карточке нажмите «Загрузить новую версию», выберите файл и опишите изменения. Локальная проверка начнётся автоматически. Файлы: PDF, DOCX, XLSX, TXT, MD, CSV, до 20 МБ. Проверка выполняется последовательно, интерфейс остаётся доступным.
4. В «Файлах и версиях» можно открыть старую редакцию, скачать оригинал, увидеть автора, время, SHA-256 и родительскую версию, сравнить извлечённый текст. Ветвление и слияние бинарных файлов не реализованы; история линейная, как последовательность коммитов. Оформление Word/Excel смотрите в скачанном оригинале. Для PDF доступен встроенный просмотр, когда текст ещё не извлечён.
5. Выделите фрагмент извлечённого текста и нажмите «Замечание к фрагменту» либо добавьте общее замечание. Цитата и обсуждение сохраняются у конкретной версии. Можно ответить в треде; исполнитель отмечает исправление, куратор подтверждает устранение. Открытые обязательные замечания ко всем версиям блокируют согласование. Новая загрузка не удаляет обсуждения.
6. В канбане куратор перемещает карточку между этапами и подтверждает новый статус. На карточке: регистрационный номер, вид, название, приоритет, исполнитель, куратор, срок/просрочка, актуальная версия, ИИ-проверка, открытые замечания, следующее действие. Сортировка внутри этапа — по сроку. Для завершения нужно согласовать актуальную версию.
7. «Уведомления» показывают загрузки, замечания/ответы, ИИ-несоответствия и ошибки, изменение статуса, наступление сроков. Есть счётчик непрочитанных, переход к документу/версии, отметка прочтения и личные настройки категорий. Проверка сроков выполняется при работающем сервере; почта и push не подключены.

Первоначальные восемь карточек и файлы — **синтетические примеры**. Оригинальные видео и материалы идеатона не включены в репозиторий.

## Доработки по диалогу от 28 октября

**Несколько вкладок одной учётной записи.** Названия в реестре и канбане — обычные ссылки: работают Cmd/Ctrl+клик, средняя кнопка и контекстное меню браузера. Кнопка **↗** рядом с документом сразу открывает отдельную вкладку, сохраняя список и фильтры в исходной. Можно одновременно открыть разные карточки. Прямые ссылки сохраняют раздел и выбранную версию при перезагрузке. Если реквизиты изменили в другой вкладке, старое сохранение отклоняется: скопируйте свой текст и обновите карточку. Фоновое обновление не перезаписывает начатое редактирование.

**Быстрый выбор без деревьев.** В форме создания и основных реквизитах появились поле «Дело · номенклатура», адресаты и редактор маршрута. Введите номер/часть названия дела и выберите вариант выпадающего списка. Реальной номенклатуры нет: четыре дела с кодами `ДЕМО-01`–`ДЕМО-04` явно демонстрационные; старым документам дело автоматически не назначается. Дело видно в реестре и канбане, по нему можно искать. Адресаты выбираются в компактном списке с подразделениями; их указание не предоставляет доступ к карточке.

**Мои шаблоны.** Откройте новый раздел в левом меню → «Новый шаблон». Сохраните вид документа, типовой заголовок, поручение, приоритет, дело, адресатов и очередь согласования/подписания. Каждый этап содержит участника и 1–365 календарных дней; можно добавить до 20 этапов, переставить и удалить их. Согласование предшествует подписанию. В «Днях на подготовку» задаётся относительный срок: например, 7 означает дату создания + 7 календарных дней. Имя и фактическую дату нового документа можно изменить перед созданием.

Нажмите у шаблона «Создать документ» или выберите его в поле «Личный шаблон» формы создания. Выбор заменяет поля формы. Уже заполненную форму также можно сохранить через «Сохранить эти настройки как личный шаблон». Файл документа загружается после создания карточки; файлы, старые сроки, статусы, замечания и решения в шаблон не входят. Шаблоны хранятся на локальном сервере, доступны только владельцу демонстрационного аккаунта, до 50 на аккаунт. Изменение/удаление шаблона не меняет созданные документы.

**Перенос настроек.** «Экспорт JSON» скачивает файл формата `eosdo-personal-template`, версия 1. В другом аккаунте «Импорт настроек» создаёт отдельную личную копию. До 64 КБ, проверка значений на сервере; неизвестное дело/участник или другая версия формата требуют исправления файла. Импорт не выполняет код и не переносит права доступа. JSON содержит имена полей, текст поручения и идентификаторы участников: перед передачей проверьте его содержимое.

Маршрут сейчас **сохраняет план очередности**, который виден во вкладке «Согласование и подписание». Отправка участникам, исполнение этапов и настоящая ЭП не подключены; действующее решение по версии принимает куратор. Версии, замечания и канбан продолжают работать в прежнем процессе. Отдельный новый принцип работы в диалоге оставлен на обсуждение.

## Настройка локальной ИИ

На компьютере обнаружена работающая **Ollama** и установленная **qwen3.5:9b**. В приложении раздел «Правила ИИ-проверки» показывает доступность модели. При остановленной Ollama файл сохранится, куратор получит сообщение о недоступности проверки; её можно запустить повторно.

Шаблоны и реальные требования организации пока не предоставлены. Начальные четыре правила — демонстрационные: наименование, основание, ответственный, срок. Куратор может изменить набор в интерфейсе (до 20 правил) и указать, что он пользовательский. Новые правила не переписывают старые отчёты; прежние согласования требуют повторного рассмотрения.

Каждый отчёт хранит версию файла, имя модели, редакцию и снимок правил, время, вывод по каждому правилу и цитаты. Цитата для положительного вывода дополнительно сверяется с текстом. Модель проверяет полноту и явные проблемы заполнения по заданным правилам; это **не нормативная экспертиза и не гарантия правильности документа**. Итоговое решение принимает куратор. При отсутствии положительного актуального отчёта он должен явно подтвердить ручную проверку; обязательные замечания всё равно нужно закрыть отдельно.

Текст отправляется только на `http://127.0.0.1:11434/api/chat`, облачные модели и внешние API не используются. Реализован [официальный контракт структурированного ответа Ollama](https://github.com/ollama/ollama/blob/main/docs/capabilities/structured-outputs.mdx). Другую уже установленную локальную модель можно выбрать при запуске:

```sh
./scripts/start.sh --model ИМЯ_МОДЕЛИ
```

Ограничения извлечения и проверки: сканы PDF без текстового слоя и защищённые PDF требуют OCR/ручной проверки; более 200 страниц, более 45 000 извлечённых символов, большие распакованные Office-файлы или превышение консервативного лимита контекста дают явную ошибку. Файл сохраняется целиком, текст для проверки молча не обрезается. Макросы, ЭП, изображения, чертежи и оформление не проверяются. Ответы модели могут ошибаться; проверка на двух синтетических примерах не доказывает качество на всех видах документов.

## Данные и восстановление

- Приложение и стили: `static/`. Сервер, SQLite и фоновые задания: `server.py`. Сборщик фронтенда не нужен; JavaScript-библиотек в браузере нет.
- База и оригиналы файлов: `data/eosdo.sqlite3`. Файл версии, метаданные, событие и уведомление сохраняются одной транзакцией. Триггеры запрещают перезапись/удаление оригинальной версии через приложение. Это не защита от владельца компьютера с доступом к БД.
- При загрузке от устаревшей базовой версии сервер отвечает конфликтом. Идентичный последней версии файл повторно не добавляется. Новая версия отменяет согласование предыдущей. Старая ИИ-проверка не меняет статус более новой версии.
- Перезапуск возобновляет незавершённые ИИ-задания. Демонстрационные сессии сбрасываются; документы, замечания, отчёты и настройки остаются.
- Для резервной копии остановите сервер и скопируйте всю папку `data`. Для восстановления остановите сервер и верните сохранённую папку. Не удаляйте `data`, если хотите сохранить документы.
- `data`, `.venv`, скриншоты тестов и документы пользователя исключены из Git. Сервер слушает только loopback, проверяет Host/Origin; публикация в сеть не выполнялась.

## Проверки разработки

```sh
.venv/bin/python -m py_compile server.py
npm run check
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
PYTHONPATH=. .venv/bin/python tests/live_ai.py
```

Последняя команда обращается к настоящей локальной модели, используя только синтетические файлы во временной базе. Проверяются документ без срока и полностью заполненный документ, а также уведомления о результатах.

Браузерная проверка (нужна запущенная Ollama):

```sh
npm ci
npx playwright install chromium
npm run test:ui
npm run test:dialogue
```

Можно указать уже установленный Chromium через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Тест запускает собственный сервер на 8771 и временную БД; после проверки удаляет их. Проверяются создание, две загрузки и настоящая ИИ-проверка, скачивание, сравнение, замечание к старой версии, смена роли, подтверждение куратора, блокировка согласования, канбан, уведомления, правила и ширина 390 px. Скриншоты остаются в игнорируемой папке `test-results`.

`test:dialogue` использует отдельный сервер 8772 и временную БД. Проверяет две вкладки одной сессии, неизменность исходного списка, личные шаблоны, маршрут, относительные сроки, экспорт/импорт, отказ на некорректный JSON, конфликт сохранения и мобильный редактор. Обращений к модели для этой проверки нет. HTTP-тесты дополнительно проверяют чужой доступ к шаблонам, границы дней/количества, атомарность и повторное открытие старых данных.

Старые вкладки нужно перезагрузить: сохранение реквизитов теперь требует номера редакции.
