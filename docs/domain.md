# Домен

Аккаунт — реальный email, пароль и профиль пользователя. Пароль хранится только в виде Bun.password hash, сессия — в Redis. Первичная регистрация создаёт организацию и куратора; остальные аккаунты — исполнители. Доступ определяется серверной сессией и ролью, не авторскими полями запроса. SSO, приглашения и восстановление пароля пока не подключены.

Документ имеет реквизиты, исполнителя, куратора, срок и этап. Версия — неизменяемый оригинал с хешем, автором и извлечённым текстом. Новая версия отменяет согласование предыдущей. Автор версии — вошедший пользователь. Замечание связано с версией; открытое обязательное замечание блокирует согласование. Личный шаблон хранит настройки реквизитов/маршрута, а не версии или решения. Папка templates содержит только примеры для ручного выбора файла и не является источником runtime данных.

События хранятся в UTC; сроки — даты YYYY-MM-DD. Ненастроенный справочник дел и правила пусты. Фиктивные пользователи и правила не подставляются. Вывод модели — недоверенные данные, недоступная проверка не равна успешной. S3/PG ошибки не должны давать фиктивный успех. Эти свойства требуют реальных проверок, текст документа их не доказывает.

Интеллектуальная обработка хранит извлечённые факты с цитатами и смысловой индекс отдельно для каждой версии. Цитата должна присутствовать в исходном тексте, значение — в цитате; для замечаний/решений сохраняется контекст предложения с отрицанием. Группы по проекту/организации/ссылке и сводки — предложения для проверки человеком, а не подтверждение актуальности или согласования. Автор ищет только собственные документы; обзор и повторная обработка доступны куратору.

## Демонстрационные пространства

Главная страница создаёт отдельный вымышленный профиль при каждой полной загрузке. Его документы, файлы, шаблоны и настройки приватны для этого пространства; реальные аккаунты и другие демо их не видят. Демоматериалы являются примерами, их статусы не означают реального согласования или электронной подписи. /login сохраняет прежний жизненный цикл реальных аккаунтов; автоматические примеры туда не добавляются.

## Сравнение и история замечаний

Версии образуют линейную цепочку parent_id. Diff доступен между выбранной и любой предыдущей версией той же карточки после проверки доступа. Сравнивается извлечённый текст по строкам с нормализацией CRLF; оформление не сравнивается. Пустая база первой версии означает добавление всего текста. Общий лимит — 500000 символов, 10000 строк и 4000000 ячеек LCS; превышение возвращает явное limited, а не приблизительный или усечённый diff.

Замечание может иметь anchor_line: номер строки выбранной версии, цитата проверяется сервером. Исходные текст/версия/автор замечания, ответы и comment_event неизменяемы в PostgreSQL. Текущий статус и resolved_version обновляются в одной транзакции с новым событием. expected_status обнаруживает устаревшее состояние, version_id — смену текущей версии. Старые клиенты без expected_status сохраняют прежнюю совместимость. Старые замечания без событий показываются как исторические данные без выдуманных переходов. Новая версия не закрывает замечания, обязательные замечания всех версий блокируют приемку до закрытия куратором.
