# Проверки

Все команды выполняются из корня с Bun 1.4.4 и зависимостями `bun install --frozen-lockfile`.

| Проверка  | Команда                | Успех и область                                           |
| --------- | ---------------------- | --------------------------------------------------------- |
| Типы      | `bun run check`        | exit 0; строгий TypeScript, не runtime поведение          |
| Сборка    | `bun run build`        | exit 0; Solid и Tailwind compilation                      |
| Формат    | `bun run format:check` | exit 0; нативный Bun fmt                                  |
| Lint      | `bun run lint`         | exit 0; oxlint 1.90.0, без ошибок и предупреждений      |
| Поведение | `bun test`             | тесты выполнены, без падений; skips раскрываются отдельно |
| Сервисы   | `bun run services:up`  | PostgreSQL, Redis, MinIO доступны; нужны Docker и .env    |

Для переноса стека обязательны типы, сборка, формат, lint и интеграционные проверки сохранения/ошибок. UI-проверка внешнего вида и пользовательских сценариев обязательна до объявления полной эквивалентности. Сбой/пропуск не считается успехом.

По явному решению владельца от 28.10.2026 используем oxlint вместо нативного Bun lint. Версия закреплена в devDependencies и bun.lock. Команда: `oxlint --deny-warnings src scripts tests vite.config.ts`. Применяются стандартные правила correctness без отключений; предупреждения запрещены. Предыдущий блокер отсутствия native lint снят этим изменением требования. Результаты: [oxlint completion](../tasks/2026-10-28-oxlint/completion.md).

CI запускает доступный набор; внешняя защита слияния и независимое ревью не подтверждены. Swiss Clock — инструкции и доказательства, а не автоматическая гарантия. Результаты конкретного запуска: [completion.md](../tasks/2026-10-28-typescript/completion.md).

## Полный прикладной набор

| ID              | Команда                    | Среда / обязательность                                                                    | Критерии / артефакт                                                                  |
| --------------- | -------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| API-INTEGRATION | `bun run test:integration` | Все 3 сервиса; обязателен при изменении API/хранения                                      | AC-04; сохранение оригинала, конфликты, замечания, доступ, JSONB; completion.md      |
| UI-SMOKE        | `bun run test:ui`          | Сервисы, dist, Chromium (`bunx playwright install chromium`); обязателен при изменении UI | AC-03; создание, upload, direct link, отсутствие pageerror; test-results/solid-*.png |

Для установленного Chromium задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Владелец требований и исключений — владелец проекта; агент не может считать обязательный пропуск успешным. CI включает интеграционный и UI набор, но успешный CI run и branch protection пока не подтверждены.

## Компоненты и локальные аккаунты

Текущая задача: [критерии](../tasks/2026-10-28-components/task.md), [результат](../tasks/2026-10-28-components/completion.md). Интеграционные и браузерные прогоны используют временные PostgreSQL базы и тестовые оригиналы в MinIO, чтобы не заполнять рабочий реестр. Обязательны сценарии пустой базы, регистрации/входа/выхода, отказа чужому профилю, ручной загрузки документа-примера, совпадения оригинальных bytes и привязки автора к сессии. Наличие файлов в templates не создаёт документов автоматически.

## Мобильное демо

`tests/demo.test.ts` в `test:integration` проверяет отдельные демопространства, отказ чтения чужих оригиналов/шаблонов, невидимость для обычного куратора, неизменность настоящей организации, ограничения прав и компенсацию S3 при отказе. `scripts/verify-ui.ts` сохраняет сценарии настоящего аккаунта через `/login` и добавляет автоматический вход, новую личность после reload, реестр/карточку/меню на 360/390px и `/demo` QR. Критерии и результаты: [mobile-demo](../tasks/2026-10-29-mobile-demo/task.md). Проверки используют отдельные временные БД и удаляют тестовые оригиналы.

## Версии и diff

`tests/version-diff.test.ts`: независимые примеры замены строки, пустых текстов, CRLF, завершающих переводов строки, повторов и перестановок; восстановление обоих входов из diff и явный отказ по лимитам. `tests/server.test.ts` в integration проверяет структурированный diff/выбор базы, чужие версии/цитаты/номера строк, историю статусов и optimistic guard, роль куратора, неизменяемость оригиналов/замечаний/ответов/событий, повторную миграцию и версии legacy без parent_id. `scripts/verify-ui.ts` проверяет сравнение desktop/mobile, переход из старой строки в замечание к правильной версии, отметку и подтверждение исправления, историю и запоздавший ответ после смены карточки. Изображения: test-results/version-diff-desktop.png и version-diff-mobile.png. Критерии и доказательства: tasks/2026-10-29-document-diff/.

Демо-версии: tests/demo.test.ts проверяет 7 оригиналов (bytes/text/SHA-256/size), цепочки 3/2/2, эталоны diff, anchor_line, акторов/хронологию open→addressed→closed, изоляцию двух участников разных demoScope и компенсацию S3 при сбое второго/шестого write. verify-ui показывает готовый diff v1→v3 и историю подтвержденного исправления без ручной загрузки. Скриншоты: test-results/demo-versions-diff-{desktop,mobile}.png и demo-version-remark-{desktop,mobile}.png. Артефакты задачи: tasks/2026-10-29-demo-versions/.

Нормоконтроль: tests/normocontrol.test.ts и OOXML-пример в extraction.test.ts проверяют независимые текстовые/структурные находки, отсутствие ложного успеха, лимит 300 и сохранность bytes. server.test.ts проверяет автоматический отчёт без правил ИИ, чужой доступ и ручную проверку старой версии без изменения оригинала; verify-ui.ts открывает вкладку, повторяет проверку и проверяет 390px без горизонтального переполнения. Артефакты test-results/normocontrol-{desktop,mobile}.png. Критерии: tasks/2026-10-30-normocontrol/task.md.
