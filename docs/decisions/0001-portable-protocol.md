# ADR-0001: переносимый протокол с отдельным подключением проверок

- Статус: принято.
- Дата: 2026-10-22.
- Основание: одобренная владельцем концепция первой версии; `tasks/0001-bootstrap/task.md`.

## Контекст

Нужен boilerplate для coding-агента в проектах с повышенной точностью. Прикладной язык, среда запуска, CI и тип проекта не определены. Нельзя честно создать универсальные тесты корректности неизвестного приложения.

## Решение

Хранить независимое ядро в Markdown: контекст, правила, цикл работы, шаблоны и основания. Для Codex использовать `AGENTS.md` как вход. Подключать исполняемые команды и ограничения слияния отдельно по спецификации целевого проекта. Первую версию обозначать как протокол, а не готовый технический барьер.

## Альтернативы

- Один большой промпт: проще переносить, но труднее поддерживать контекст, основания и проверяемые артефакты.
- Собственный runtime агента: требует неподтвержденных решений о провайдере и оркестрации; не нужен для согласованного объема.
- Универсальный CI с проверкой наличия файлов: может создавать ложное впечатление проверки корректности приложения.

## Последствия

Ядро можно перенести в разные проекты и адаптировать к разным агентам. До настройки конкретных проверок и внешних ограничений технического запрета приемки ошибок нет. Markdown требует проверки актуальности и поведения агента. Решение пересматривается, если появится требование к автоматическому исполнению протокола или конкретному стеку.
