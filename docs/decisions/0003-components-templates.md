# Компоненты и документы-примеры

Дата: 2026-10-28. Источник: требование владельца к развиваемой архитектуре и отсутствию моков; уточнение: templates содержит только примеры документов, загрузка выполняется из своих профилей.

Solid-компоненты выносятся в layout/shared/features, состояние и API — в отдельные модули. Fastify bootstrap отделяется от регистрации маршрутов и доменных операций. Остаются TypeScript/Bun1.4.4, Tailwind, Fastify, Drizzle, PostgreSQL, Redis, MinIO и oxlint. Новые UI frameworks, state managers и SDK не нужны.

Фиктивные учётные записи и организация удаляются. Приложение не заполняется фиктивными документами, делами или правилами. Реальные данные профиля вводит пользователь; автор документа и файла берётся из серверной сессии, не из клиентского author_id.

Папка templates содержит MD/TXT примеры с полями для заполнения. Backend её не читает и автоматически ничего не импортирует. Пользователь вручную выбирает файл при загрузке из своего профиля. Личные шаблоны реквизитов в PostgreSQL — отдельная существующая функция, папка с ней не связана.

Тестовые данные создаются только во временных базах и каталогах. Прежняя локальная база eosdo сохранена, приложение переключено на пустую eosdo_workspace. Автоматического удаления существовавших документов нет. Для Railway сохраняется разделение: Docker Compose только для локальных сервисов, UI/API — Railpack; оригиналы файлов — постоянный MinIO.

Владелец выбрал локальные аккаунты email/пароль. Используем встроенный Bun.password, Redis cookie-сессии и уникальный нормализованный email в PostgreSQL. Первый аккаунт — куратор, дальнейшие — исполнители, выбор роли при регистрации не принимается. Саморегистрация — сознательная локальная модель без SSO/invite, которую можно заменить отдельным identity provider позже.
